# Paper Exp.2 Cross-Layer Coordination Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement conflict-density scenarios, an independent exact oracle, SANet-DW*, and the complete four-method Exp.2 pilot and figures.

**Architecture:** Adapt the existing cross-layer proposal and feasibility framework to a method-independent density/type generator. Every method uses the same bounded candidate action space; only Proposed performs explicit hard-feasibility arbitration before the shared transaction verifier.

**Tech Stack:** Python 3, asyncio, existing Stage 4 cross-layer core, exact enumeration, NumPy, Matplotlib, unittest.

**Spec:** `docs/superpowers/specs/2026-08-20-paper-experiments-finalization-design.md`

## Global Constraints

- Base scenario is 20 business Agents, 10 Gateways, and 28--32 DAG edges.
- Conflict density is `[0,10,20,30,40,50,60]%` and is the only main x-axis.
- Conflict mix targets A/B/C/D proportions 25/20/20/35.
- Solvable/infeasible labels come only from the independent exact oracle.
- Methods are `proposed`, `sanet_dw`, `adjacent_layer`, and `independent` on one candidate action space.
- FSR/QSR denominators contain solvable cases only; SRR contains infeasible cases only.

def test_conflict_mix_is_not_all_cascaded(self):
    kinds = [generate_conflict_snapshot(60, 4, index).conflict_types
             for index in range(20)]
    flattened = Counter(kind for group in kinds for kind in group)
    self.assertEqual(set(flattened), set(PaperConflictType))

- [ ] **Step 3: Implement dynamic-weight global optimization**

Compute nonnegative application/transport/network/physical weights from
normalized current objective violations and normalize them to one. Score every
shared candidate combination with the weighted soft objective and select the
best deterministic combination. Do not invoke hard feasibility or transaction
pre-verification inside SANet-DW*.

- [ ] **Step 4: Map Independent and Adjacent-Layer to final policies**

Independent chooses each layer's local best action and combines them without
arbitration. Adjacent-Layer permits only a-t, t-n, and n-p pair coordination and
does not run a four-layer joint solve. Proposed uses existing exact feasible
combination search, priority arbitration, and shared verification.
