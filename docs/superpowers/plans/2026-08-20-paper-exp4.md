# Paper Exp.4 Failure Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Adapt the existing failure framework to the final three failure families, add NetKeeper*, and complete the four-method Exp.4 pilot and four figures.

**Architecture:** Reuse the current failure snapshots, CSPF, impact analysis, RuleDelta, transaction executor, and stable verifier. Narrow Agent Failure to active business Agents, express capacity stress as reduction percentage, and add a network-configuration adaptation baseline without Proposed-only reasoning.

**Tech Stack:** Python 3, asyncio, existing Stage 5 simulator/CSPF, NumPy, Matplotlib, unittest.

**Spec:** `docs/superpowers/specs/2026-08-20-paper-experiments-finalization-design.md`

## Global Constraints

- Base scenario is 24 business Agents, 12 Gateways, and approximately 36 edges.
- Main failure types are Agent Failure, Link Failure, and Capacity Degradation at 30%.
- Capacity stress is `[10,20,30,40,50]%` reduction.
- Methods are `proposed`, `netkeeper`, `cspf`, and `full_rebuild`.
- `RuntimeEvent` is the latency start; no physical detection claim is allowed.
- CSPF must remain competitive for link failure and must not gain cross-layer inputs.

    self.assertTrue(snapshot.failed_link_in_active_task_path)

    snapshot = generate_paper_failure_snapshot("CAPACITY_DEGRADATION", 0.30, 5, 0)
    self.assertAlmostEqual(snapshot.post_capacity_mbps,
